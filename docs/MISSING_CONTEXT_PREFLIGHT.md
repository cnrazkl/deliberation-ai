# Critical missing-context preflight — DA-070

This is a narrow owner-coaching gate before a new council run, not a semantic completeness or correctness classifier. It uses local deterministic `missing-context-v1` rules and makes no provider call. The source is the owner's question, never instructions inside a PDF, memory entry or tool result. It currently asks at most two questions for concrete legal action (jurisdiction and event date), medication dose changes (medicine/current dose/age), or tax action (jurisdiction and tax year). It can miss indirect language or details supplied only in an attachment; it can also ask when sufficient information is already present in an unfamiliar format. The owner may explicitly proceed with the original question.

## Workflow

The normal token/prompt/risk preview marks matching questions before submission. On submission the server repeats attachment, prompt and risk checks. If critical context appears missing, it creates an encrypted `awaiting_input` preflight draft and returns HTTP 202. No run or queue job exists yet. The UI lists these drafts after a page reload. The owner can enter up to 1,500 characters of additional context, choose to retain the original question, or cancel. The original text is never overwritten: an answer is appended under a visible owner-clarification label.

Each choice requires a fresh preview of the resulting question, first-round member instructions/user text, approximate tokens and effective risk. The start request includes both reviewed prompt and risk fingerprints. The server reloads the saved request, revalidates attachments and selected context, rebuilds both previews and rejects stale fingerprints. It also checks the frozen draft and choice in the run transaction. A successful start atomically creates the run/queue job, stores the decision and original question encrypted on the run, and scrubs the draft's encrypted request/question payload. Cancellation scrubs those payloads without creating a run. Started and cancelled draft stubs retain status metadata; run retention may null the link after deleting an old run. The single-run JSON export includes the decision provenance.

DA-071 adds [revision selection](PROMPT_REVISIONS.md) after this clarification step. The clarified base is preserved as that revision's original; the pre-clarification owner question remains separately in the preflight decision. Changing the candidate or selected version requires another preview before start.

The selected members, models, reasoning settings, review count, attachments and selected memory/tool records are frozen from the original submission. If these need changing, cancel the pending draft and submit a new task. A changed/removed context item, attachment or risk requirement can cause preview/start to refuse the draft; an owner must create a new task. A completed draft's idempotent start request returns its run, so a browser retry does not create another model job. Unanswered drafts persist locally until the owner cancels or starts them; there is currently no expiry.

Schedules have no interactive owner at dispatch time. Creation and activation reject questions matching the missing-context policy; a legacy active schedule that would require a question is paused at dispatch without advancing its occurrence or calling a provider. The owner can recreate it with sufficient context. Existing queued and historical runs are not retroactively stopped.

## Storage and boundaries

Migrations `0027_misty_siren.sql` and `0028_fast_enchantress.sql` add `preflight_drafts` and nullable `runs.preflight_decision_ciphertext`. The draft's question/request and the run's choice, answer, original question and frozen question list use context-bound authenticated encryption. The question ids and policy version stored in the draft's JSON contain no user text. Drafts are owner-scoped and mutation routes require same-origin requests. Preview responses are no-store; neither full prompts nor submitted answers enter application events or ordinary logs. The exhaustive backup verifier includes all three new ciphertext fields. Optional preview image dimensions are retained only in the encrypted draft request, for resuming the local token estimate; they do not change the provider payload.

The policy only detects a few explicit patterns. A nonempty answer is not proof that the missing information was supplied. DA-071 adds optional owner-controlled, additive revision after clarification, without a semantic optimization claim; later-round prompt inspection remains separate work. This gate does not replace the `risk-rules-v1` control floor or professional review.
