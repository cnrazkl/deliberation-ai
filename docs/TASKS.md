The owner can save a bounded claim-scope note and an explained relation between two claims; encrypted report updates preserve provenance, evidence and synthesis state. Browser, domain and PostgreSQL tests cover the workflow. This does not discover unextracted source claims, infer semantic contradiction or validate truth.

- **DA-044:** a normalized analyst claim with mixed `objection` and other claim kinds no longer enters shared ground solely because two model identities repeated its text. The complete group, member quotes and stable id remain under different views; new groups default to unresolved synthesis coverage. Older encrypted reports are reclassified on read while owner evidence/coverage annotations remain intact, and the UI explains the classification split. This is a conservative presentation guard, not semantic contradiction or scope detection.

- **DA-043:** the owner-facing council no longer starts in or offers local demo mode. File selection now remains available with saved connections, appends up to six images/PDFs, displays validation failures, and defaults member attachment sharing on. Selectable-text PDFs are parsed locally, verified again before encrypted enqueue, sent as untrusted round-0 text only to consenting members, and included in the preflight token estimate. The PDF route works in development and a production build; offline tests cover mixed attachments and a full browser submission. Deterministic fake adapters remain for automated tests and historical compatibility, with no paid provider test in this increment.

- **DA-042:** shared analyst claims now require distinct selected model identities, not merely different council seats. Repeated claims from one model stay visible with every occurrence, while old encrypted reports are reclassified on read from their frozen member configuration without discarding claim ids or owner annotations. This does not infer semantic equivalence or prove that model aliases are independent.

- **DA-034:** durable SSE is the primary progress transport; cursor polling remains the automatic startup fallback.
- **DA-035:** owner-authorized capture accepts bounded HTML, plain text and selectable-text PDF snapshots. PDF parsing is limited to 1 MiB, 100 pages, 64,000 extracted characters and a separate ten-second parse deadline.
- **DA-036:** a run can freeze up to six JPEG/PNG/WebP/GIF inputs (2 MiB each, 12 MiB total). Each member has an explicit per-task opt-in; native OpenAI, Anthropic, Gemini and OpenAI-compatible adapters translate the same immutable bytes into their own multimodal request shape. Review rounds never resend images.
- **DA-037:** local Streamable HTTP MCP connections are restricted to loopback. The owner discovers and invokes an allow-listed tool explicitly; encrypted text results can be selected manually or retrieved with a deterministic lexical top-3 search. Models receive only frozen, untrusted result text and cannot call tools.
- **DA-038:** daily and weekly local schedules freeze the question and complete council configuration, start paused, and require explicit activation. The worker scans every 30 seconds, uses a schedule/occurrence idempotency key and preserves the created run id.
- **DA-039:** research capture can optionally render JavaScript pages in an isolated headless browser. Every HTTP(S) document/script/data request still uses the pinned-DNS public-network retriever; non-GET, image, media, font, WebSocket, service-worker and download paths are blocked and request/byte/time limits apply.
- **DA-040:** local preflight shows an approximate first-round input-token total and per-member text/image breakdown, including selected memory and tool context, before a task can be sent. No provider call or database write is made for the preview. Server image signature validation and loopback-only web binding were added during the full-app review.
- **DA-041:** the empty-input token display was corrected to zero; user question/image tokens are separated from remote council instruction overhead. Fake perspective meaning is explained in the UI, the editable member role is included in real provider instructions, and the historical PLAN.md was fully compared with the running application in [PLAN_GAP_AUDIT.md](PLAN_GAP_AUDIT.md).
