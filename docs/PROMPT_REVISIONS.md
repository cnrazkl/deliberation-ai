# First-round prompt revisions — DA-071

The local interface keeps the owner's original question visible and offers an optional deterministic **structured candidate**. This candidate appends a short response frame about uncertainty, counterarguments and invented sources. It makes no model call and is not a measured optimization or a claim of improved accuracy. The owner can edit the candidate or select the unchanged original. For critical missing-context questions, clarification comes first; the revision editor then operates on the original plus the owner's explicit answer. The pre-clarification original remains separately preserved in the run's preflight decision.

The candidate must contain the complete original text **exactly once**. The editor shows the exact added prefix and suffix in the normalized text that will be submitted (leading/trailing whitespace is trimmed), and flags omission, duplication, oversize text or a changed policy version. This mechanical check prevents silent deletion or rewriting of the owner's words, but cannot establish semantic equivalence, harmlessness or correctness of added instructions. The first-round prompt/risk/token preview is recalculated from the selected text. The current conservative risk rules cannot be lowered by choosing a candidate containing the full original; newly added risk terms may raise the effective floor. The server repeats revision validation, normal risk checks and prompt/risk fingerprint checks before enqueue. A changed choice or edit invalidates the visible preview.

For a new run, migration `0029_burly_riptide.sql` adds nullable `runs.prompt_revision_ciphertext`. The server stores the original, candidate, selected choice and independently recomputed mechanical/risk audit under context `run:<id>:prompt-revision`. Direct API calls without revision fields receive an identity revision; historical rows remain null. Run details and an explicit single-run JSON export expose this provenance to the local owner. Bounded history and ordinary event logs do not contain the text. The backup verifier includes the new ciphertext field.

This is revision visibility and owner control for round 0. It does not add an LLM optimizer, an independent semantic transformation auditor, provider-side hidden prompt inspection or later-round previews. The structured candidate is only an optional format request. A semantic quality comparison would require the separate human/empirical acceptance work already documented in the project.
