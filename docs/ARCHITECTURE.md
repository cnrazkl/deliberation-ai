# Architecture

## DA-118 conversation council usage

A pure domain projection groups retained council operation counters. Persistence reads
bounded indexed membership, metadata-only live receipts and authenticated deletion audits
in one owned snapshot; a no-store BFF returns only counters. ConversationPanel renders
independently timestamped council/private views and binds loaded data to its run ID.
No schema/adapter/worker change. [Contract](CONVERSATION_COUNCIL_USAGE.md).

## DA-117 browser-local private defaults

An allow-listed non-sensitive localStorage value supplies private defaults. An SSR-safe
external-store editor synchronizes saved values across tabs. PrivateBranchesPanel
snapshots the default on branch opening/creation into its existing draft map; global
updates cannot mutate active delivery review or retry intent. No server storage/API
change. [Contract](PRIVATE_DELIVERY_SETTINGS.md#da-117-browser-local-default).

## DA-116 private setting draft continuity

PrivateBranchesPanel owns ephemeral output-cap drafts by branch ID and controls the
delivery selector. Receipt/revision changes still remount the review/intent component;
only the cap selection survives. Confirmed deletion removes its draft. No storage or
provider boundary changes. [Contract](PRIVATE_DELIVERY_SETTINGS.md#da-116-draft-continuity).

## DA-115 conversation private usage

A pure domain projection deduplicates origin receipts across retained branches and
deletion audits. Persistence reuses bounded authenticated loaders in one owner-scoped
read-only snapshot; a no-store BFF returns metadata only. Conversation-keyed client
requests abort/fence stale responses and reuse the counter renderer. No schema, queue
or provider changes. [Contract](CONVERSATION_PRIVATE_USAGE.md).

## DA-114 private usage projection

A pure domain projection groups validated private receipts by connection/model and
counter conventions. PrivateUsagePanel renders it from the existing owner-scoped
branch DTO. No BFF, persistence, worker or adapter change; no external branch/audit
aggregation. [Counting policy](PRIVATE_USAGE.md).

## DA-113 private output settings

Shared strict contracts bound the optional per-send cap; domain rendering freezes it
into the existing private input. Persistence binds it to preview/replay fingerprints and
the encrypted receipt. The BFF validates the read-only query and send payload; the UI
invalidates review on edits. Adapter mappings use the existing request field. No new
table or SDK boundary. [Contract](PRIVATE_DELIVERY_SETTINGS.md).

## DA-112 responsive layout

The main column is a named CSS inline-size container. Panel layout breakpoints follow
its available width independently of the viewport-controlled sidebar. A visible attachment
button delegates to the existing file input/ref and validation path; no API or persistence
contract changes. [Design and responsive acceptance](UI_DESIGN.md).

## DA-111 workspace shell

WorkspaceShell owns responsive navigation and appearance. CouncilWorkbench keeps the existing task/configuration state and mounted panels while switching hidden views. The sidebar reuses owner-scoped conversation/run discovery; private conversation reviews render in the main area. LocalSchedulesPanel opens an exact existing lastRunId through the same saved-run handler. Theme preference is a non-sensitive browser key, synchronized through a small external store and applied before paint. Existing BFF, queue and provider boundaries remain unchanged. [Design](UI_DESIGN.md).

## DA-110 runtime/test lifecycle

Interactive `pnpm dev` uses loopback 3000 and `.next/`; Playwright owns `dev:e2e` on
3100 and `.next-e2e/`. The wrapper fixes APP_ORIGIN after local env loading. Test
teardown owns its launched tree; database/queue sharing remains unchanged.
[Operations and verification](OPERATIONS.md#da-110--separate-interactive-runtime-from-browser-tests).

## DA-109 Markdown exports

Existing owner-scoped run/conversation export routes accept `format=md` and pass safe
DTOs to pure web formatters. JSON remains the default. Conversation snapshot boundaries
are reused; Markdown adds literal fencing and a formatted-byte limit. No database or
provider mutation. [Contract](MARKDOWN_EXPORTS.md).

## DA-108 saved template lifecycle

Persistence owns request identity/hash, exact-row review and encrypted deletion receipts. Owner advisory and table locks serialize save/delete. Active-name uniqueness permits fresh name reuse while owner/request uniqueness preserves deleted intent. The BFF exposes bounded same-origin preview/confirmation; UI retains retry identity and fences review responses. Run/schedule snapshots and provider/queue boundaries remain independent. [Contract](COUNCIL_TEMPLATE_LIFECYCLE.md), [ADR-0033](adr/0033-reviewed-council-template-deletion.md).

The BFF creates a run and a pg-boss job in one PostgreSQL transaction. Before enqueue, it resolves the requested 2–6 members and stores their full configuration as a context-bound encrypted snapshot. The separate worker leases the job and holds a per-run PostgreSQL advisory lock on a dedicated session through the running checkpoint, remote execution and final publication. An overlapping delivery observes the existing run without invoking a second executor. The holder executes round 0 concurrently outside a database transaction, then executes up to three requested parallel cross-review rounds among successful members, with a barrier and frozen prior-round input between rounds. It stops after an incomplete round. Durable per-member/per-round provider receipts replay known results after a restart without resubmission. It commits analysis output, review output, normalized claims, provenance, the final report, and an ordered completion event together. Re-delivery observes a terminal run and does not duplicate results. Queue notifications wake the worker promptly; a one-second polling fallback handles missed notifications on this local installation.

An explicit same-origin `POST /api/runs/:id/export` loads the local owner's terminal run through the existing owner-scoped repository and creates a versioned JSON projection. The projection allow-lists run metadata and the complete report; it does not serialize the full run record, credentials, internal request/queue keys or attachment bytes. The response is an attachment with `no-store` and `nosniff`. The browser downloads it only after the owner clicks the report button; generation makes no provider call or database write.

`GET /api/runs` returns a 20-row owner-scoped history page sorted by creation time and run id. An opaque-to-the-UI run-id cursor is resolved inside the same owner scope, then a keyset query retrieves older rows. The query selects only listing fields and a report-presence boolean; it decrypts the selected questions but does not load report bodies, member snapshots, attachments or credentials. The browser opens a selected row through the existing owner-scoped `GET /api/runs/:id` and resumes SSE observation for an active run. Selecting another run cancels the old browser watcher, leaving server-side execution unchanged.

`GET /api/runs/:id/usage` reads existing provider-operation receipt counters for the local owner. Database aggregates sum all non-null input/output counts and separately count missing reports, while the detail list is capped at the newest 100 attempts. The response selects no encrypted result, raw text, prompt, credential or citation fields. Each attempt retains round, attempt number and outcome; an unknown or failed outcome is not translated into zero spend. DA-082 adds a read-only token-estimate ledger and partial subtotal to this visibility projection; settled invoice accounting and monetary reservations remain open.

If a provider returns text but fails the output schema, the adapter carries that text only in a normalized known failure. The receipt stores it encrypted even without parsed output; a restarted worker reloads it rather than repeating the provider call. The application passes it into the failed member or review entry, and the final report plus `model_runs` store it encrypted. Failed text never enters claim grouping, peer-review packets or a successful result projection.

The run snapshot may also contain up to six bounded image or PDF attachments. The server verifies each digest and file signature. The same-origin `/api/runs/prepare-pdf` route extracts selectable, page-marked PDF text before submission; enqueue repeats extraction and checks that client-supplied text exactly matches the bytes before context-bound encryption. PDF.js remains external to Next's server bundle so its Node worker module resolves beside the installed package in development and production. `receiveAttachments` is frozen per member: the application removes attachments and extracted documents from a member request unless this flag is explicitly true. Provider adapters translate allowed round-0 images into native content parts and PDF content into untrusted text; cross-review receives peer structured text only and never resends attachments. A same-origin, no-store local preflight route resolves the same selected memory and tool context and uses the shared round-0 prompt builder to estimate input tokens before enqueue. Image costs are approximate and PDF text is counted for opted-in members; the route sends nothing to providers and persists nothing.

The persistence retention boundary scopes both preview and explicit delete to the fixed local owner, terminal statuses and `finished_at` before a calculated cutoff. Correlated checks exclude runs with prepared, submitted, unknown or retry-authorized provider/decision attempts, or a queued/running/unknown decision assessment. The CLI previews by default. `--apply` locks eligible run rows, removes their recorded council/decision jobs from the pg-boss partitioned table and deletes the runs in one transaction; foreign keys cascade through run-owned tables and set a schedule's last-run link to null. Queue ids are validated before deletion, so bad metadata rolls back rather than silently leaving a partial deletion. Fixture-only integration tests cover all known run-owned table families and recorded queue jobs without pruning owner history. Existing archive/export copies and live replacement recovery remain separate operational work.

The local backup command uses the provisioned PostgreSQL 18.6 `pg_dump` custom archive and an adjacent SHA-256 manifest. The final manifest is published only after verification; an unsuccessful attempt removes its new archive and pending manifest so latest-backup discovery cannot select it. Verification checks the hash before creating a random temporary database, restores with `pg_restore --single-transaction --exit-on-error --no-owner --no-privileges`, checks application and pg-boss tables, and scans every restored encrypted database field in bounded keyset pages. Its explicit field/context inventory must match all restored `*_ciphertext` columns; each non-null value must decrypt with its row-bound context, and JSON envelopes must parse. This check validates envelope readability, not application-level semantics or successful replacement recovery. The recovery rehearsal also inventories run/provider-operation statuses and active schedules without starting a worker. PostgreSQL credentials are passed through child-process environment variables rather than command-line arguments, and tool stderr is not forwarded because it can contain SQL or user data. The administrator connection creates and drops only the generated verification database. The command does not restore into the active database or package the encryption key.

The worker keeps one dedicated PostgreSQL session for its lifetime and writes a heartbeat every 15 seconds after queue registration and schedule startup. The session sets an instance-specific `application_name`; shutdown marks the row stopped and releases it. The read-only local diagnostics query counts a worker as ready only when its heartbeat is newer than 45 seconds, is not stopped, and a matching session exists in `pg_stat_activity` for the current database. A heartbeat restored from an archive therefore cannot alone claim a worker is live. The same query returns only aggregate local-owner run, unresolved-operation and schedule counts. The web route has no queue initialization, provider call or mutation.

`POST /api/provider-connections/:id/models` is an explicit local-owner catalog check. The route rejects cross-origin requests, loads one owner-scoped encrypted connection secret and passes it to the provider package's bounded catalog adapter. Native OpenAI, Anthropic and Gemini list APIs and OpenRouter's user-filtered list use their own request shapes; other compatible endpoints are probed only at the saved base URL's `/models` path. The adapter returns bounded model ids and status, never a provider response body or credential. It does not call the generation adapter or schedule a run. The latest normalized result is encrypted onto the owner-scoped connection row only if its revision still matches the one read before the network request. Saving connection settings increments that revision and clears the prior result. The ordinary connection list decrypts this latest result for the local UI; it is not a historical or complete capability ledger.

The same adapter now projects only documented model metadata from official catalog responses into bounded typed fields. Claude effort levels require an explicit `supported: true` entry; Gemini token limits and `thinking`, and OpenRouter context length and a reasoning-parameter presence signal, remain provider-reported observations. Custom compatible catalogs contribute ids only. The check timestamp and data are retained as one encrypted latest-result snapshot; no model-policy decision is made from it.

That shared builder also renders the exact first-round `instructionsFor` and `inputFor` strings for each member. It fingerprints version `council-v1`, member/provider settings, rendered strings and image digests; the text preview omits raw image bytes. The browser submits the fingerprint, enqueue recomputes it after freezing selected context and verified attachments, and the worker recomputes from the encrypted run snapshot before calling any provider. Enqueue returns a conflict for a changed preview; a worker mismatch becomes a failed report with `prompt_snapshot_mismatch` and no model call. Historical rows with a null fingerprint remain executable. The preview does not include provider framing or a future cross-review prompt.

Package direction is `contracts <- domain <- application`, with provider and persistence implementations entering through application ports. The provider-independent `evaluation` package depends on `domain` for the council report type and claim-transfer audit while its separate decision-evaluation contracts remain offline. Raw output and normalized claims remain separate. API DTO validation uses Zod. Sensitive content must not be emitted to general logs.

The application passes the frozen member configuration to the domain report builder. Analyst agreement groups count normalized model identities rather than seat ids; fake-mode identities also include the selected demo perspective. Read-time report hydration applies the same classification to older encrypted reports without rewriting their claim provenance or owner annotations. Model aliases can still obscure a shared underlying model, so this grouping remains a presentation heuristic, never proof of independent verification.

The domain also withholds a normalized claim from shared ground when its analyst occurrences mix `objection` with a different claim kind. The complete group, its quotes and stable claim id remain in the distinct projection. Read-time reconciliation applies this conservative rule to older encrypted reports; prior evidence and synthesis annotations are preserved, with a review notice in the UI if an older “included” annotation now sits on a distinct claim. No semantic contradiction or factual correctness is inferred from claim kinds.

The browser primarily subscribes to `GET /api/runs/:id/stream?after=<sequence>` over Server-Sent Events. Every message contains the durable events after the supplied cursor and the current run projection; the event id is the latest committed sequence. The stream sends keepalives, closes on a terminal run, and can reconnect without relying on process memory. If the stream cannot start, the client falls back to `GET /api/runs/:id/events?after=<sequence>` cursor polling. `GET /api/runs/:id` remains the direct result lookup, and `POST /api/runs/:id/cancel` records cancellation before cancelling the queue job.

`PATCH /api/runs/:id/claims/:claimId/evidence-state` validates a closed evidence-state enum and updates the claim row, encrypted report projection, run version, and event ledger in one locked transaction. Grouping and occurrence counts never infer or promote evidence state. Legacy reports hydrate missing states as `unsupported`.

`PATCH /api/runs/:id/claims/:claimId/synthesis-coverage` uses the same locked claim-annotation transaction for `included`, `omitted`, and `unresolved`. New shared analyst groups start included; distinct and red-team groups start unresolved. The projection never deletes a claim and does not appoint a provider or model as a synthesis authority.

The domain builds a claim-transfer audit from validated member `parsed.claims` and all report occurrences. It detects missing, duplicate, unexpected, and field-altered occurrences; read-time hydration recomputes it for historical reports. `PATCH /api/runs/:id/claims/:claimId/scope` and `POST|DELETE /api/runs/:id/claim-relations` validate owner-authored scope and pairwise relation input, then rewrite the encrypted report in a locked run transaction with a content-free event. These post-run records do not modify model outputs, claim evidence state, or synthesis coverage. No provider call or database migration is required.

Run and local-schedule contracts carry the owner's `standard|high` preference. DA-069's pure domain rules derive an effective control floor from the question and delivered context; a match or uninspected image requires red-team and cross-review at enqueue. The application binds the assessment, prompt digest and review count in the preview fingerprint; persistence saves effective risk and the encrypted versioned assessment. Creation, activation and dispatch of schedules all enforce the floor; dispatch pauses a legacy schedule with missing controls. The worker rejects mismatches between the frozen assessment and required controls before calling a provider. Existing post-run checks still require successful red-team participation, exact peer-review coverage and intact claim transfer. This is a bounded lexical control policy, not semantic verification or a measured classifier. [Policy and compatibility](RISK_PREFLIGHT.md).

`GET|POST|DELETE /api/memory-entries` manages the single owner's encrypted, bounded memory library. POST accepts only an existing persisted claim reference and snapshots its current statement, source type, and evidence state. A run request contains at most five memory ids; the BFF resolves owner-scoped entries before enqueue and stores an encrypted immutable memory-context snapshot on the run. The worker passes the same snapshot to every member, and it participates in provider-operation fingerprints.

`GET|POST|DELETE /api/evidence-sources` and `PATCH /api/evidence-sources/:id` manage owner-reviewed source records. Manual creation does not fetch its URL. Titles, URLs, notes, and excerpts are encrypted. POST freezes the excerpt, optional publication date, and server capture time; a database trigger rejects later snapshot-field changes. PATCH can change only content-review and freshness-review states and records the freshness decision time. Claim evidence-state mutation requires the matching relation, verified review state, and `current` freshness state in the same locked transaction. Review downgrades and deletion are blocked while the claim's current state depends on the source.

`GET|POST /api/research-captures`, `PATCH /api/research-captures/:id`, and `POST /api/research-captures/:id/promote` form a separate owner-initiated retrieval boundary. The `retrieval` package accepts only public HTTP(S) targets on standard ports, validates every DNS answer, pins the socket lookup, handles redirects manually with revalidation, and bounds time, bytes, headers, content types and extracted text. Direct mode decodes HTML/plain text or extracts selectable PDF text. Optional browser mode uses a fresh isolated Playwright context, blocks service workers/downloads and routes every document, script, stylesheet and data request back through the same pinned retriever. It rejects non-GET and non-text resources, stops after 20 requests/5 MiB/15 seconds and persists only normalized body text. Persistence encrypts the requested/final URLs, title and frozen plain text. Rejecting a capture changes only its research review state. Promotion requires an exact substring of the frozen text and creates a separate unreviewed evidence record atomically; it makes no claim-state change. See [ADR-0018](adr/0018-application-managed-retrieval.md).

The local tool boundary is separate from model execution. `packages/tools` accepts only loopback Streamable HTTP MCP endpoints. The owner explicitly discovers and invokes a currently listed tool; encrypted bounded text results enter a small local result library. Run creation freezes at most three selected results, or deterministic lexical retrieval chooses up to three before persistence. Providers receive these results only as labeled untrusted round-0 context. Provider output cannot initiate tools, and review rounds receive no tool context. See [ADR-0019](adr/0019-local-mcp-result-boundary.md).

Local schedules reuse the existing run aggregate and pg-boss queue. A schedule stores an encrypted immutable question/member template, cadence and next occurrence. Creation always starts paused. The worker scans active due schedules at startup and every 30 seconds, enqueues with a deterministic occurrence key, links the resulting run and advances the next time. See [ADR-0020](adr/0020-local-schedules.md).

Native OpenAI Responses, Anthropic Messages, and Gemini GenerateContent adapters plus a separate OpenAI-compatible Chat Completions adapter exist behind the same `TextProvider` boundary. The worker resolves the member's saved connection and constructs only the matching adapter. This allows mixed remote councils without leaking provider-specific values into application or domain code. The immutable member snapshot also carries its normalized reasoning level and explicit web-search mode. Native adapters translate automatic search into the provider-specific tool contract; the compatible adapter does so only for the OpenRouter preset. Each network call receives a durable operation id. The worker writes `prepared` and `submitted` receipts before the call, then persists either an encrypted successful result, normalized citation metadata, a known failure, or `outcome_unknown`. A submitted or unknown operation is never called again automatically. Successful encrypted results and citations can be replayed after a worker crash without another provider charge.

Provider operations are keyed by run, member, round, and increasing attempt number. An `outcome_unknown` receipt appears in the local operator projection. Discard closes that exact attempt as `discarded`. Explicit retry authorization closes it as `retry_authorized`, atomically clears the stale report, and requeues the run. Successful analysis and review calls replay their encrypted receipts; the affected stage receives a new operation id and attempt number. Every operator action is appended to the run event ledger.

Cross-review input is derived only after round 0 settles. A reviewer receives the original frozen question and validated summary/claims of every other successful member. Raw response text is excluded; self output is supplied only by the explicit DA-077 self-revision option. Review output must cover every supplied peer, name no unknown target, and use one of three explicit stances. Review failure is preserved separately and makes the run partial without deleting successful round-0 analysis.

Council templates store the same validated member configuration used by runs. Templates are mutable conveniences; a run never points to mutable template state and always owns its encrypted member snapshot. Each member carries a provider family, exact task model, role, provider-connection id, normalized reasoning level, and web-search mode. Provider connections are addressed by id and store credentials, a starting model, endpoint, and protocol capabilities. Editing a saved connection does not mutate templates or historical run snapshots.

The member snapshot also carries an explicit council role. Domain grouping builds shared and distinct projections only from analyst occurrences. Red-team occurrences are grouped independently into `redTeamChallenges` and always retain disputed presentation status. This separation happens after provider validation and before persistence, so provider prompts cannot elevate a red-team opinion into authority or analyst agreement.

The browser's one-action red-team control only edits the same validated member configuration used by ordinary runs and templates; it introduces no alternate queue or provider path. The comparison projection is derived at render time from persisted analyst groups, persisted `redTeamChallenges`, and labeled cross-review records. It deliberately performs no semantic claim matching and persists no winner or score, so the domain report and provenance remain the source of truth.

Sensitive run content and provider credentials use AES-256-GCM envelopes with context-bound authenticated data. PostgreSQL keeps only ciphertext plus non-sensitive indexes, state, hashes, and model identifiers. The master key remains in ignored local environment configuration.

## Decision evaluation boundary

[ADR-0017](adr/0017-advisory-decision-evaluation.md) adds an optional `DecisionEvaluator` port alongside, rather than inside, `TextProvider`. The `evaluation` package owns provider-independent decision contracts; `providers` supplies deterministic fake and direct TypeSafe implementations. A separately initiated post-run pg-boss job evaluates a frozen claim/source pair and persists a typed assessment with its own operation receipt. The worker registers this queue only when `ENABLE_DECISION_EVALUATOR=true`; the shipped default is off. No new service or workflow engine is required.

The data flow is `persisted report + owner-selected immutable excerpt + explicit sharing confirmation -> encrypted assessment snapshot -> decision adapter -> separate shadow projection`. It cannot alter council rounds, evidence states, synthesis coverage, minority visibility, or run completion. The direct TypeSafe adapter sends only the frozen claim, selected excerpt, and fixed rubric metadata to `/v1/systemone`; it does not fetch the source URL. Errors mean unassessed, unknown outcomes block automatic retry, stale results remain historical, and an unavailable decision provider cannot prevent the council from completing. Advisory promotion remains locked until the [evaluation gate](EVALUATION.md) passes.
