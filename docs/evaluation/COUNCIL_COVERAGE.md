# Council claim coverage measurement

DA-068 adds [the external-source correctness workflow](COUNCIL_CORRECTNESS.md). It prepares a separate 40-case multi-domain candidate suite, requires an explicit human independence/coverage attestation, and uses `loadStoredCouncilMeasurementRuns` for acceptance-grade binding of the **source-inclusive** frozen question, configuration and provider receipts. The legacy question-only API described below remains diagnostic. Scores now include separate development/held-out slices and critical denominators; empty recall denominators are null. Human labels and model measurements are still pending.

DA-049–DA-051 provide an offline measurement contract for **source-level claim recall**. It is separate from the optional TypeSafe/JEV source-support evaluator. A source document and question define a case; each human-authored gold claim has an exact character span in that source and a critical flag. Span offsets use JavaScript string (UTF-16) positions and must match the frozen source text exactly after decoding. Cases carry Turkish, English or mixed language, risk tags and development/held-out splits. A source cannot cross those splits.

An assessed case records its run id and one explicit human decision for every gold claim: `represented`, `missing` or `uncertain`. `represented` requires a linked occurrence and a rationale. The caller supplies one loaded `CouncilReport` with its case and run id for each assessed case; the evaluator derives occurrence ids from the report's shared, distinct and red-team claim groups and first audits exact transfer from the validated member outputs. It rejects missing/duplicate or mismatched runs, broken claim ledgers, missing gold decisions and invented occurrence ids. Failed or unavailable runs use `not_assessed` without a report, rather than a false semantic label. The assessment no longer accepts a caller-authored occurrence inventory. The caller remains responsible for loading the authentic encrypted run and its report; this offline function does not fetch or authenticate database records.

For locally persisted runs, call `evaluateStoredCouncilCoverage(corpus, assessment)` from `@deliberation-ai/persistence`. It loads each assessed run under the local owner's scope, decrypts and hydrates its report, requires a completed or partially completed status, and compares the stored question exactly with the corpus case before calling the pure evaluator. It makes no model request and writes no evaluation result. The corpus source text and human gold labels are still supplied by the evaluation operator; this function does not prove their provenance or adjudicate semantic correctness.

The score reports represented, missing, uncertain and unassessed counts; definite critical misses separately; and a conservative recall interval. The lower bound counts only represented claims. The upper bound allows uncertain and unassessed claims to be represented, so it is not an accuracy estimate. Language and risk-tag slices keep their denominators visible. The small synthetic test cases validate schema and arithmetic only.

Before using this to claim council quality, build the planned 40-case bilingual/risk corpus from real source/question families, obtain independent human review and adjudication for held-out labels, freeze the split and thresholds, load authentic run reports, and run opt-in model evaluations. Semantic matching is **not** automated here. Preserving malformed raw output and exact structured-claim transfer are separate controls; neither proves that all important source claims were found.

The offline [labeling gate](COUNCIL_LABELING.md) assembles an adjudicated corpus from a frozen source intake, two independent review sheets and a separate adjudication record. The [review worksheet workflow](COUNCIL_REVIEW_WORKSHEETS.md) prepares distinct review files, compiles exact source quotes to evidence offsets and then prepares a third-person adjudication worksheet only after both reviews exist. No human labels have been entered. These tools validate structure and produce corpus/labeling hashes only after complete inputs; they do not create real labels or prove reviewer independence.
