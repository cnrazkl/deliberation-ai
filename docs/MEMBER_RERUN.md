# Selected-member follow-up (DA-079)

DA-081 optionally carries the source run's frozen execution-limit configuration into its child with fresh call/output allowance. Reused round-0 results reserve nothing; the selected initial attempt and fresh reviews must fit, and explicit manual retries consume additional allowance. Source reservations are unchanged. Local acceptance verification passed on 1 October 2026. [Verification evidence](REPO_AUDIT_2026_10_01.md). This does not add semantic synthesis or a monetary/input/tool cost ceiling. [Execution-limit contract](EXECUTION_LIMITS.md).

The 29 September audit serializes concurrent identical follow-up intents and keeps an unchanged browser intent key after a lost response. Later retries return the existing child; a delayed response does not steal focus from another opened run. Enqueue checks every connection required by fresh reviews, not just the selected initial member. [Regression evidence](REPO_AUDIT_2026_09_29.md). Mounted-page retry state does not persist through refresh, and these controls do not impose a token/money budget.

A completed remote council can start a new versioned `member-rerun-v1` run for one selected member. The new run freezes the original question, attachments, context, member settings, prompt digest, risk controls and successful round-0 results of every other member. Only the selected member receives a new round-0 provider call. If reviews were selected, every reviewer receives the newly combined round-0 set in fresh review rounds. The child builds a new deterministic claim ledger and quality projection; the source report is never replaced.

The owner initiates this from a completed result. The UI shows the selected review count and an upper bound of `1 + member count × review rounds` new provider calls for this submission, excluding any later explicit operator-authorized retry. Tokens, provider web search and monetary cost cannot be predicted exactly. The endpoint is same-origin, owner-scoped and idempotent. It rejects partial/legacy or tampered source snapshots, incomplete round-0 membership, unresolved source provider attempts, changed prompt fingerprints and risk controls that no longer meet the current floor. It never calls a provider while creating the follow-up; the ordinary worker and receipt rules govern later calls.

The child stores an encrypted, run-bound copy of reused raw/parsed outputs, citations and source run id. This keeps it executable and auditable if the source is later deleted. Reused results are marked in the child report. Successful new calls receive child-specific receipts; reused round-0 results create no new provider operation. The original and child appear as separate saved runs and exports.

This rebuilds the structured report; it does not generate or semantically validate a free-form final answer. Previously saved connection settings may have changed since the source run, so the new provider call uses the current saved connection for the selected member. A different endpoint behind a model id is not proven equivalent. No live paid provider call was made during implementation tests.

While the local application worker is running, use `pnpm test:integration:isolated` to create, migrate, test and remove a random disposable database. This keeps the worker from claiming a test job. The regular `pnpm test:integration` command remains available for environments without a concurrently connected worker.
