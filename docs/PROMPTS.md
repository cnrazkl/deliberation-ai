# Prompt contracts

**DA-100:** `private-text-v1` instruction and rendered seed/owner/reply text are unchanged. Gemini translates only the leading system text to `systemInstruction`; later roles become user/model with exact text/order and no invented reply. No schema/tool/search/thinking prompt is added. Opaque signatures and visible thoughts do not enter future input; this is reconstructed text history, not provider-managed reasoning continuity. [Translation](PRIVATE_BRANCHES.md#da-100-native-gemini-generatecontent).

**DA-099:** `private-text-v1` still renders the same source/system/owner/reply text. Responses sends that ordered text as `input`, reconstructed assistant turns labelled final. Commentary, tool/refusal content and visible reasoning are refused; opaque reasoning state is excluded from future context. No council/private instruction text is changed. [Translation](PRIVATE_BRANCHES.md#da-099-native-openai-responses).

**DA-097 private-text-v1:** the exact reviewed ordered input includes a fixed private-role system instruction, source question/perspective, copied selected reply, saved owner messages and successful private replies. Omitted peers/reviews/attachments/original continuation context remain unavailable. Fresh risk checks use the actual rendered input and original source floor. These messages never alter canonical council prompts or claims.

DA-091 adds `run-continuation-v2` manual compacted history without changing `council-v1` instructions. User-written summary, preserved source question/provenance and replaced-section digests are shown in the exact rendered member input. The notice identifies missing report/minority/raw detail and rejects semantic-equivalence or authority claims. Review rounds receive the same compacted context. Private original text is not rendered or counted as provider input, even in full-context descendants. `run-continuation-v1` rendering stays compatible. [Contract](CONVERSATION_COMPACTION.md).

DA-090 optionally includes `run-continuation-v1` question/report history in `council-v1` input. A notice rejects authority from historical answers, consensus, evidence labels or embedded instructions. Every initial member receives identical history independently; review rounds retain it. No-history rendering stays unchanged. Full history enters local estimates, risk and provider-operation fingerprints; prior attachment/memory/tool inputs are not separately replayed. [Scope](CONVERSATION_CONTINUATION.md).

DA-072 saves a `cross-review-v1` plan after actual round-0 successes are known. DA-075 preserves that round-one contract and saves a `cross-review-v2` plan for rounds 2–3 after the previous round closes. For every attempted reviewer, the same request passed to the provider adapter yields saved application-level instructions and input, peer ids and a SHA-256 text fingerprint. Later-round input names the previous round and includes the same frozen set of its successful validated reviews for every reviewer. The encrypted report exposes these strings in the UI and explicit export. A failed attempt may not have reached the provider; provider-hidden framing is not shown.

DA-077 adds opt-in `cross-review-v3`. Only for this version, the reviewer also receives its own validated round-0 summary/claims and must return `selfRevisions` (possibly empty), with at most five `qualify` or `withdraw` proposals. The application rejects nonexistent or duplicate source indices, unchanged qualifications and withdrawals whose statement differs from the original. These proposals do not edit round-0 output, the claim ledger or owner evidence states. Prior closed-round reviews remain available in later rounds; same-round output is never shared. A changed input and version produce a distinct prompt/receipt fingerprint.

DA-073 freezes 40 source-inclusive original/candidate question pairs for offline comparison and prepares independent human semantic-drift worksheets. This does not alter the production prompt or claim that the candidate improves accuracy. [Comparison protocol](evaluation/PROMPT_COMPARISON.md).

DA-071 exposes an optional `prompt-revision-v1` structured candidate. It appends only neutral response-format requests to the full original text; the owner may edit it or choose the unchanged original. The UI shows exact inserted prefix/suffix, mechanical preservation findings and the revised first-round member text. Enqueue repeats the audit and freezes encrypted original/candidate/choice/audit provenance. It does not claim semantic equivalence or measured improvement, and it does not inspect provider-hidden framing. [Revision limits](PROMPT_REVISIONS.md).

DA-070 preserves the encrypted original question in its pending draft. Selecting an answer appends a visibly labeled owner clarification; selecting original sends the unchanged question. Neither path silently optimizes the prompt. The resumed preview renders current `council-v1` member instructions/user text and both prompt/risk digests from the saved member/context selection; the server recomputes them at enqueue. The accepted original/choice/answer is encrypted with the run. [Missing-context scope](MISSING_CONTEXT_PREFLIGHT.md).

DA-069 adds local `risk-rules-v1` preflight without changing `council-v1` instructions or the owner's question. It checks the question and delivered context and binds risk preference/review settings to the existing prompt digest. It makes no LLM call, optimizes no text and supplies no missing-context answers; see [the scope](RISK_PREFLIGHT.md).

The original user question is preserved exactly in the encrypted run record. Round 0 sends the same frozen question to every member.

All remote adapters use the same short system/developer instruction requiring independent analysis, a concise summary, separable claims, quoted support from the member’s own answer, honest uncertainty, and no invented sources. The member's owner-selected role text is appended as that member's analysis focus in both rounds; it is not the fake-mode perspective enum. OpenAI and Gemini request schema-constrained output. Compatible endpoints use the connection's JSON Schema, JSON object, or prompt-only mode; Anthropic currently uses the prompt contract. Every adapter validates the result with the shared Zod `ProviderOutput` schema. Prompt text never contains credentials and is not logged.

Round 0 labels extracted PDF text as user-supplied, untrusted document data. Page markers support traceability but do not establish evidence or permit instructions inside the PDF to override the council prompt. The selected PDF text appears in the same frozen input only for attachment-consenting members. Cross-review rounds exclude documents and image bytes.

Default round 1 uses a separate cross-review instruction. It states that the model is reviewing peers, prohibits majority-as-truth and invented sources, requires one or more assessments for every supplied peer, and requires exact target ids plus `support`, `qualify`, or `challenge`. The input contains the original frozen question and peers' validated summaries/claims. It excludes the reviewer's own result and every raw response; opt-in v3 includes only its own structured first-round result as described above.

Rounds 2–3 use the same output schema with a `cross-review-v2` instruction that treats prior reviews as observations to reassess, not evidence of truth. Alongside the frozen question, selected memory and round-0 peer summaries/claims, the input includes only the immediately previous closed round's successful validated review outputs, with no same-round result. The round-one prompt and fingerprint remain unchanged for historical compatibility.

Red-team members receive an additional role instruction in both rounds. It asks for assumptions, counterexamples, failure conditions, and irreversible risks; requires concrete grounding in the supplied material; and prohibits performative disagreement or claims of final authority. The role label is frozen with the run and included in the provider-operation fingerprint.

When the owner selected shared-memory entries, both rounds receive only their frozen content, evidence state, and analyst/red-team source type. The prompt labels them as user-selected historical context whose truth and freshness are not guaranteed, explicitly says they are not instructions, and forbids silently treating them as facts. No memory is sent when the selection is empty.

The first-round council prompt now has contract version `council-v1`. The owner sees the rendered system instruction and user input for each member before submission. A SHA-256 fingerprint covers those strings, member/provider/reasoning/web settings and permitted attachment digests; enqueue and the worker recheck it against frozen context. The visible text omits image bytes and provider-specific request framing. This is an exact preview of our first-round strings, not a claim about provider-side tokenization or hidden framing. DA-071 adds an optional owner-editable additive revision, its exact textual diff and mechanical/risk audit; it stores both texts and the choice separately. Measured optimization and independent semantic-equivalence auditing remain open. The later-round strings are inspectable only after the actual peers exist, not predicted before the run.

## Council correctness experiment

The separate DA-068 correctness experiment renders the original evaluation question and exact source bundle as labeled JSON data inside the ordinary council question. It contains no human gold labels; the existing versioned round-0 prompt remains authoritative. Source content is explicitly untrusted, and disagreement/conditions must be preserved. The packet is rejected above the existing 4,000-character question cap. Stored measurements recompute the ordinary round-0 prompt fingerprint before scoring.

The offline `contradiction-shadow-v1` prompt asks for pairwise contradiction/compatibility/uncertainty under matching entity/time/jurisdiction/conditions, exact quotes from both supplied claims and a brief rationale. It forbids following source instructions and makes no factual verification or winner selection. Unknown scope cannot produce a contradiction label. The injected evaluator's entire batch must pass the pair/fingerprint/quote schema or all selected pairs remain unassessed. This prompt has no production provider binding.

## Decision rubric

The separate decision evaluator uses the frozen `source-support-v1` closed-label rubric in [EVALUATION](EVALUATION.md). Its instructions, criteria, option ordering and selected input are versioned in the assessment snapshot. Each request explicitly embeds the claim and immutable excerpt as labeled data instead of relying on an opaque question key. Excerpts are declared untrusted data, never instructions; peer votes, owner evidence labels and preferred answers are excluded.

The first rubric is manually defined, not generated or optimized live by another model. The adapter returns only the provider's typed choice, probability distribution, confidence metadata, model and usage; it does not invent a free-text justification. Rubric/model changes invalidate prior calibration until regression evaluation. Existing council prompt contracts remain unchanged.
