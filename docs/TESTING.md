DA-059 adds a PostgreSQL fixture-only retention test. It checks that preview leaves data intact, explicit apply deletes an old terminal local-owner run and its model runs, claims, occurrences, events and provider receipt, while preserving a recent terminal run, an active run and another owner's old run. This retention test does not run the unscoped operator apply command against existing local history or prove complete account deletion; backup verification is covered separately in DA-060.

DA-060 exercised `pnpm db:backup` against the existing local database, then `pnpm db:backup:verify` on the saved archive. PostgreSQL custom-format restore into a generated disposable database recovered 182 run rows, the expected application/queue tables and one encrypted question decryptable with the current key; cleanup left the active database untouched. A copied manifest with an altered SHA-256 was rejected before restore. This is an operational rehearsal of this backup artifact, not a replacement-installation recovery, provider-state reconciliation or test of every encrypted field.

The PostgreSQL queue-recovery fixture uses a one-second notification fallback, matching the local worker. Both integration files cancel test-created queue jobs before deleting their runs so later test runs do not inherit orphaned work. During DA-050 verification, PostgreSQL was initially stopped; after startup and cleanup of orphaned test jobs, all eight integration cases passed.

Further queue hardening should add injected transaction rollback and commit/ack crash tests before production deployment. Those cases are separate from the accepted local Phase 0b slice.

Live provider tests remain manual and opt-in. They require an explicitly configured local credential and model, may incur provider cost, and never run in ordinary checks.

DA-028 supplies the schema, frozen synthetic fixture, metrics, [labeling protocol](evaluation/CORPUS_AND_LABELING.md), and [pre-registration](evaluation/PRE_REGISTRATION.md). DA-029 now tests adapter parsing, exact version pinning, conservative failures, receipts/replay, encryption, cancellation, stale inputs and isolation from council annotations. These checks make no live request and claim no accuracy from a fake provider. DA-030 is an owner-deferred, separately enabled held-out comparison. If reopened, advisory promotion still depends on its quality gate. Neither typed output nor high provider confidence is an acceptance test for factual correctness, and the deferred pilot is not a blocker for the accepted local council.
