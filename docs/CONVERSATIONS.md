Audit rows use logical conversation IDs and survive later DA-095 empty metadata deletion. External downloaded/backup copies retain what they captured. [Contract](PRIVATE_BRANCH_DELETION.md).

DA-096 additionally retains [selected-member private owner drafts and prefix forks](PRIVATE_BRANCHES.md). The conversation library reopens these even without a surviving run body. The earlier DA-093/094 scope below is extended by this increment; actual sending/replies and message editing/deletion remain open.

Every new independent run creates a durable conversation. Full/compacted continuations and selected-member reruns inherit their immediate source's conversation in the same transaction as the new run and queue job. Idempotent retries do not create another conversation or membership. This grouping changes no provider input, memory selection or execution policy.

The opened result's **Konuşma** panel identifies the conversation, lists every retained member and opens saved results without replacing the new-run draft. **Konuşmayı indir (JSON)** downloads all its retained branches in one database snapshot. It includes current questions/status, prompt/risk provenance, member-rerun provenance, reports with raw/minority outputs, delivered history and private original compaction archives. Queued/running/failed/cancelled entries remain explicit, including null reports. The file is plaintext, including private archives. Separate attachment bytes, memory/tool/evidence records, provider receipts/billing and decision assessments are not bundled; this is not a database backup.

## Retention and completeness

`conversations` records owner, identity, anchor run UUID, origin and creation time. `conversation_runs` retains only owner, run UUID, conversation UUID, immediate source UUID, kind and creation time. It deliberately has no run foreign key. Deleting a run removes its content under the existing retention rules, while membership metadata preserves the conversation and source graph. Missing content is marked unavailable, never reconstructed as a full run from another run's copied history. Descendants retain their own frozen histories under their existing retention lifetimes.

Conversation metadata is retained even when all member bodies are gone; no automatic metadata deletion is introduced. DA-095 adds [explicit reviewed deletion of one empty conversation metadata record](CONVERSATION_DELETION.md). The broader backup/export, retained-body and future model-private-message deletion policy remains open. Owned run UUIDs, including retained unavailable members, can resolve a conversation through `GET /api/runs/:id/conversation`; `POST /api/conversations/:id/export` accepts its durable identity. The verified DA-094 discovery list is documented below. Renaming, merging, moving branches, model-private threads and message-level storage remain separate work.

The export schema is `deliberationai-conversation-export-v1`. It includes the complete recorded membership list, per-run availability and an explicit list of missing historical source boundaries. A read-only repeatable-read transaction prevents mixing membership and report versions across concurrent writes. Available links are checked against authenticated run provenance; membership drift, cycles and disconnected/wrong-conversation roots reject the snapshot. Foreign conversation IDs return no data, and download POSTs require the existing same-origin boundary.

The whole snapshot is limited to 200 recorded members and 32 MiB. Stored row size is checked before loading bodies and final UTF-8 JSON size after projection. Exceeding either limit returns 413 without a partial export; the UI points to single-run downloads. No field contains credentials, encrypted storage envelopes, idempotency keys or request hashes. This does not certify historical statements or summary fidelity.

## Legacy rollout

Apply migration `0043_pink_naoko.sql`, restart old application/worker processes, then run `pnpm db:conversations:index`. It first completes the existing authenticated branch index and then atomically groups owned runs by surviving immediate-source links. Matching missing source anchors group surviving siblings without fabricating missing records. Existing native memberships are preserved and validated. The operation uses the same owner advisory lock as enqueue, before row locks; a grouping failure rolls back the conversation transaction. The earlier branch-index step may have committed its own valid batches.

The legacy command is bounded to 10,000 owned runs, 10,000 existing membership rows and 128 MiB of encrypted continuation/rerun provenance. It fails visibly rather than partially grouping larger histories. Repeating it is idempotent. Pending owned runs keep conversation views/exports unavailable until grouping is complete. Continuation/rerun creation from an ungrouped source is rejected atomically; existing independent runs can still execute.

Membership creation copies the original PostgreSQL timestamp directly, preserving sub-millisecond precision. The indexing command also corrects initial rollout timestamps only when their millisecond projection and authenticated source/kind match; it does not repair materially different timestamps or reassign conversation identity. Backup restore checks owner/link/timestamp consistency and reports retained/unavailable member counts. Archives predating both conversation tables remain readable; a partially present conversation schema is rejected.

Legacy conversations carry `legacy-reconstructed` provenance. Links deleted before this migration cannot always be recovered: disconnected components may remain separate conversations. The UI and export state this limit. A later restored conflicting bridge requires explicit recovery rather than silently merging established conversation IDs. New native memberships preserve future deleted intermediates as metadata.

## Verification

### Standalone discovery — DA-094

`GET /api/conversations` adds an independent conversation list, without requiring a currently opened run. The list uses 20-item pages ordered by conversation creation time and UUID, rather than latest activity, so continuing an older conversation does not move its cursor position. Full PostgreSQL timestamp precision is preserved. Invalid cursors return 400; absent or foreign cursors return 404. Pending owned legacy indexing returns 503 instead of an apparently complete library. Responses use `Cache-Control: no-store`.

Each entry contains conversation identity, creation time, native/legacy origin, recorded/available/unavailable member counts and the latest available owned run's id, status and question. No report/private archive/attachment/provider/accounting body is fetched. Metadata-only entries stay visible, with opening disabled. This list is a discovery projection, not a certification of the complete branch graph; existing conversation detail/export still authenticates that graph and enforces its own size limits. Listing itself is not limited to conversations of 200 members or 32 MiB, because no full conversation snapshot is loaded.

The **Kayıtlı konuşmalar** panel opens the saved run through the existing workbench callback and preserves the question, model choices and continuation draft. It sends no generation request. Explicit retry and refresh are available; a refreshed first page rejects late older-page results. DA-095 adds explicit empty-metadata deletion. Rename/merge/move, model-private messaging and deletion of retained/private bodies remain separate work. Primary application acceptance and the additional saved-history refresh regression are recorded in [the audit](REPO_AUDIT_2026_10_02.md).

Offline PostgreSQL tests cover concurrent enqueue/replay, full/compacted siblings, actual source retention and later descendants, private archive export, queued/null-report state, legacy missing anchors, idempotent migration, cycles, owner isolation, disconnected-root drift and all-or-error size limits. Existing rerun tests verify immediate-parent membership inheritance. Browser acceptance downloads and parses the actual JSON from a loopback mock flow, checks complete source/child membership, same-origin rejection, preserved drafts and no extra provider calls. No paid/live-provider call is authorized by this feature.
